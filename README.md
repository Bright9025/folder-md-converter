# 📦 Folder-MD-Converter

[English](./README.en.md) | [简体中文](./README.md)

一款轻量级的文件夹 ⇄ Markdown 双向转换工具，提供图形化界面，可将整个文件夹导出为单个或多个 Markdown 文件，也可将符合规范的 Markdown 还原为完整的文件夹结构，并内置 **AI 输出规范生成器**，帮助其他 AI 按格式输出可还原的内容。

</div>

## ✨ 功能特点

- 🖱️ **图形化操作** – 基于 `tkinter`，选择文件夹或 Markdown 文件即可完成导出与还原，无需命令行。
- 📤 **文件夹 → Markdown** – 递归遍历目录，生成包含目录树、文件统计和完整文件内容的 Markdown。
- 📥 **Markdown → 文件夹** – 解析由本工具导出的 Markdown（单个 / 母+子 / 多个），还原为真实的文件夹结构与文件内容。
- ✂️ **自动拆分** – 当导出内容超过设定阈值时，自动生成一个**母文件**和若干**子文件**，便于分块阅读或喂给 AI。
- 🧩 **母文件自动合并** – 还原时若选择母文件，会自动发现并合并同目录下的所有子文件。
- 🌐 **多语言界面** – 内置简体中文、English、Français、Español、Русский、العربية 六种语言，一键切换。
- 🤖 **AI 规范生成器** – 一键导出「文件夹 Markdown 格式规范」，可直接发给其他 AI，指导它们输出可被本工具还原的 Markdown。
- 🛡️ **安全还原** – 拒绝绝对路径、拒绝 `..` 路径穿越、自动处理 Windows 保留字，防止文件写到目标目录之外。
- 🔤 **智能编码处理** – 导出时按 `utf-8-sig → utf-8 → gbk → big5 → latin-1` 顺序尝试解码，兼容中英文环境下的各种文本文件。
- 🧱 **二进制与超大文件保护** – 自动识别二进制文件，超大文件仅记录元信息不导出内容，避免 Markdown 体积爆炸。
- 🎨 **兼容 Markdown 围栏** – 若文件内容本身包含连续反引号，自动使用更长的代码围栏，避免内容被截断。

- **单文件程序** – 所有逻辑（导出、拆分、还原、AI 规范生成、多语言）集成在一个 Python 脚本中，无需额外依赖，复制即用。
- **内置 AI 规范** – 仓库已随附中英文两份 AI 输出规范文件，可直接发给其他 AI 使用，无需手动生成。

## 🚀 如何使用

### 环境要求

- Python 3.8 或更高版本
- 标准库依赖（无需额外安装）：
  - `tkinter`（Windows / macOS 官方安装包自带；Debian/Ubuntu 需要 `sudo apt install python3-tk`）
  - `os`、`re`、`threading`、`traceback`、`pathlib`、`datetime`

### 1. 运行程序

在终端中执行：

```bash
python folder-md-converter.py
```

程序启动后会看到一个带标签页的窗口，顶部工具栏包含**语言下拉框**和**生成 AI 规范文件**按钮。

### 2. 导出：文件夹 → Markdown

1. 切到「**导出**」标签页。
2. 点击「选择…」选择要导出的目标文件夹。
3. 可选配置：
   - 是否包含隐藏文件 / 文件夹（以 `.` 开头）。
   - 单文件内容大小上限（MB，0 = 不限制）。
   - 拆分阈值（MB，0 = 不拆分）。
4. 点击「**开始导出**」，选择母文件的保存路径。
5. 导出完成后：
   - 若未超阈值：只生成一个 Markdown 文件。
   - 若超过阈值：生成一个母文件 + 若干 `xxx_partNN.md` 子文件。

### 3. 还原：Markdown → 文件夹

1. 切到「**还原**」标签页。
2. 点击「选择 md 文件…」选择一个或多个 Markdown 文件。
   - **只选母文件即可**：程序会自动发现同目录下的所有子文件并合并。
3. 选择「还原到文件夹」的目标目录。
4. 点击「**开始还原**」，程序会逐个还原文件，进度与日志实时显示。

### 4. 使用 AI 规范文件

- 仓库已随附两份规范文件：
  - **`AI输出规范_文件夹Markdown格式.md`** – 中文版
  - **`AI_Guide_Folder_Markdown_Format.md`** – 英文版
- 直接把对应语言的规范文件发给其他 AI（ChatGPT、Claude、Gemini、DeepSeek 等），即可让它们按格式输出可被本工具还原的内容。
- 也可以点击程序顶部「**生成 AI 规范文件**」按钮重新导出：
  - 中文界面下会导出中文版规范；
  - 其他语言界面会导出英文版规范。

## 📄 Markdown 格式说明（核心）

本工具采用一种**轻量、人类可读、AI 可生成**的 Markdown 格式。核心规则如下：

### 文件内容块（必须）

每个文件都以块头开头，路径写在反引号中：

```markdown
### 1. `src/main.py`
```

- `N` 从 1 开始，全局连续递增。
- 路径**相对于根目录**，使用 `/` 分隔。
- 路径不能是绝对路径，不能包含 `..`。

### 内容（必须）

内容用代码围栏包裹，最少 3 个反引号：

```markdown
```python
print("hello")
```
```

### 编码标记（可选）

若文件不是 UTF-8，可加 HTML 注释：

```markdown
<!-- 文件编码：gbk -->
```

也兼容英文写法：`<!-- encoding: gbk -->`

### 二进制 / 超大文件（可选）

用 `> 说明` 代替内容即可：

```markdown
### 3. `logo.png`

- 文件名：`logo.png`
- 文件大小：12.34 KB

> 二进制文件，未导出内容。

---
```

还原时这种文件会被创建为空文件（占位）。

### 完整示例

```markdown
# 文件夹内容导出：demo

- **根目录**：`/tmp/demo`
- **导出时间**：2026-01-01 12:00:00
- **文件总数**：2
- **文件夹总数**：1（不含根目录）
- **包含隐藏项**：否
- **单文件内容上限**：10.0 MB
- **拆分阈值**：不拆分

---

## 一、目录结构

```
demo/
├── src/
│   └── main.py
└── README.md
```

---

## 二、文件内容

### 1. `README.md`

- 文件名：`README.md`
- 相对路径：`README.md`
- 文件大小：15 B

<!-- 文件编码：utf-8 -->

```text
# Demo
Hello, world!
```

---

### 2. `src/main.py`

- 文件名：`main.py`
- 相对路径：`src/main.py`
- 文件大小：20 B

<!-- 文件编码：utf-8 -->

```python
print("hello world")
```

---
```

### 拆分输出（可选）

若内容很长，可拆分为一个母文件和多个子文件：

- **母文件**：包含元数据、目录结构、以及一个索引表：
  
  ```markdown
  | 子文件 | 覆盖文件序号 | 文件数 | 链接 |
  |:---|:---|---:|:---|
  | `xxx_part01.md` | 1 - 120 | 120 | [打开](./xxx_part01.md) |
  ```

- **子文件**：文件名形如 `<母文件名>_partNN.md`，内容为若干 `### N. \`path\`` 块（编号全局连续）。
  还原工具会自动发现并合并所有子文件。

## 🎨 自定义与扩展

- **修改代码块语言映射**：编辑 `EXT_LANG_MAP` 和 `SPECIAL_FILES` 两个字典，为新扩展名或特殊文件名指定语言标记。
- **修改头部元数据**：编辑 `_build_header` 函数，自定义母文件顶部显示的字段。
- **修改子文件命名规则**：编辑 `generate_markdown` 中的 `part_name` 格式化语句。
- **新增界面语言**：在 `LANGS` 列表中添加语言代码，并在 `TRANSLATIONS` 中补充对应的键值对即可。
- **扩展还原解析**：`parse_markdown_text` 负责从 Markdown 中提取文件块，可按需扩展以支持其他自定义语法。

## 🌐 平台与兼容性

- **运行平台**：Windows / macOS / Linux，凡支持 `tkinter` 且 Python ≥ 3.8 即可运行。
- **输出格式**：生成的标准 Markdown，兼容任何 Markdown 渲染器（GitHub、Typora、Obsidian、VS Code 等）。
- **AI 兼容**：随附的中英文规范文件已被主流大语言模型（ChatGPT、Claude、Gemini、DeepSeek 等）识别，可直接作为系统提示词的一部分。
- **阿拉伯语界面**：文本已本地化，但由于 `tkinter` 对 RTL 布局支持有限，控件排列仍为 LTR。

## 🧠 技术亮点

- **流式遍历与排序** – `walk_sorted` 采用深度优先遍历，每个目录内先子目录后文件，各自按名称排序，保证目录树与内容顺序一致。
- **后台线程 + 主线程回调** – 导出与还原都在独立线程执行，进度通过 `root.after` 回到主线程刷新 UI，长时间任务不卡界面。
- **拆分规划预先估算** – 导出前先收集每个文件的大小估算，再按顺序累加，超过阈值即切块，避免单块撑爆。
- **路径穿越防护** – `safe_join` 会拒绝绝对路径、`..` 路径，以及解析后跳出目标目录的路径；Windows 保留字自动加前缀 `_`。
- **编码回退机制** – 读文件时按多编码顺序尝试，写回时优先使用 Markdown 中记录的编码，无效则回退 UTF-8。
- **围栏自适应** – `safe_fence` 扫描内容中最长的连续反引号，返回足够长的围栏，防止 Markdown 被意外截断。

## ⚠️ 局限性

- 程序读取文本文件时**一次性载入内存**，对于超大单文件（>500MB）可能内存不足；建议对超大文件配合「单文件内容上限」使用，让其只记录元信息。
- **二进制文件不导出内容**，还原时仅创建空文件占位，无法完整复原原始字节。
- **阿拉伯语界面**由于 `tkinter` 限制，未做完整 RTL 镜像布局。
- **不还原文件权限、时间戳等元数据**，仅还原文件内容与目录结构。
